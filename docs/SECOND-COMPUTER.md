# 在另一台电脑继续

## 拉取与阅读

```powershell
git clone https://github.com/tz924/huidou-ai-guide.git
cd huidou-ai-guide
Copy-Item config/machine.example.json config/machine.local.json
python scripts/validate.py
```

先填写本地配置中的绝对路径。所有相对素材路径均以仓库根目录为基准。machine.local.json 已忽略，不跟随 Git 在不同机器间互相覆盖。

在 Codex 中把克隆目录添加为本地项目文件夹；在 Claude Code 中以该目录作为工作目录。不要在子目录另建一套相互冲突的手册。把 prompts/RESUME.md 中的指令发给该 AI。

## 软件和工具

灰豆是 Windows 软件，须在实际操作的 Windows 电脑安装、打开并登录。仓库不含安装程序，也不复制用户登录态。先只读确认版本、额度、默认下载目录和当前画布；新版本按钮变化需记入指南。

给该 AI 配置能控制这台 Windows 桌面的工具，并确认能截图、识别窗口和执行一次无付费动作。仓库可在云端编辑，但不因此获得 Windows 桌面或安装能力。云端 Windows 的灰豆安装、授权和控制方案尚未实测。

## 数据迁移分两类

1. 本仓库证据素材：evidence/media 中已有三条镜头、单镜头和18秒练习导出、四格图片及字幕，可直接查看或重新导入。manifest.json 给出大小和 SHA256。
2. 灰豆工程及原始角色参考：不在本仓库完整备份。新机正式入口已确认：项目库→行末省略号→导出项目；新机用“导入项目”选择`.huidou-project`文件夹本身。同机重开已测，但本次包未复制上传MP4，仅保存本机缓存路径；稍后重启已确认带“（导入）”后缀的副本，修正早期延迟画面观察。照片包可带出PNG，但不能类推视频和声音也已完整。跨机图片、视频、声音和时间线完整性仍待验，先保留各机现有项目备份。不要直接复制未知 AppData 数据库或覆盖新机数据。原始四张参考和素材库角色需要用户同步原文件、使用软件正式导出功能，或经授权重建。

如果新机看不到“红盐/漫剧202610181520”，建立独立迁移测试项目。当前已证实画布上传节点可导入并播放已有MP4，**尚未找到外部MP4直接填回导演台成片的正式入口**；重建三镜头导演台仍为0/3，不得把媒体导入写成时间线迁移或恢复生成引用链。优先取得旧机正式工程包并单独保留媒体，再验证导入。生成新镜头前重新绑定真实图像和声音，核对数量及参数。

## 进度同步

开始先 `git status`，工作树干净时 `git pull --ff-only`；有本地修改先保存处理。结束更新状态/清单/证据，校验后 commit/push。两台电脑同时编辑要处理合并，不用 force push。实际灰豆任务状态以现场界面为准，Git 不同步任务队列。
